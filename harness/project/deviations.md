# Deviations from harness/core

Only what is listed here overrides `harness/core`. Each entry states **scope**, **reason** and **what to do for new code**.

| Rule in core | Deviation in this project | Scope | Reason | New code |
| --- | --- | --- | --- | --- |
| 02 §2 Layering `components → hooks → obr → model/utils` | `components → hooks → manager → storage (interface) → storage/local \| obr`. The SDK is still imported only in `src/obr/`, where `ObrStorage` implements the storage interface. | whole app | Several interchangeable storage backends (Owlbear, localStorage, later a cross-tab bridge); the app must run outside Owlbear. | Components talk only to hooks, hooks only to `src/manager/`. The manager knows only the `InventoryStorage` interface. Backends are listed in the storage registry. |
| 02 §3 Ready handling (gate rendering on `useObrReady`) | The popover does not wait for OBR unconditionally. If Owlbear reports ready, the Owlbear storage is chosen automatically; otherwise the storage selection dialog is shown on every start. | `src/components/app/`, storage registry | Standalone tab for dev and testing. | Never block the UI on `obrReady` outside the Owlbear storage. Load the Owlbear backend via dynamic `import()`. |
| 04 §Models: choose class vs plain type | Domain entities (`Item`, `ItemInstance`, `Character`) are classes with private fields and get/set accessors **for every value**, even without behavior. Plain types only for `ItemLocation` and `Rarity`. | `src/model/` | Accessors are the hook point for later extensions (e.g. unidentified items). | Follow 04 §Models for classes (`serialize` / `static deserialize`, DTO not exported). Mutate via the manager's `update…(id, fn)` on a clone. |
| 01 / 03 Prefer Owlbear theme colors | Own simplified dark D&D-style theme, see [design.md](design.md). | all CSS | Product decision. | Use the tokens from `src/index.css`; no literal colors in component CSS. |
| 05 Rule 4 (design for misbehaving clients) | GM notes are hidden **in the UI only**. They are readable by players via dev tools. | GM notes | Accepted by the project owner for a trusted group. | Never present GM notes as secret in UI texts. Do not store anything truly confidential in them. |
| 01 Tests optional | Vitest is used for `src/model`, `src/storage` and `src/manager`. | tests | Claude cannot use Owlbear; logic must be verified automatically. | Add tests next to the code (`*.test.ts`) with every model/storage/manager change. Run `npm run test`. Vitest ≥ 5 (3.x pulls a critical `tinypool` advisory). |
